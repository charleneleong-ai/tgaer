\begin{abstract}
We tested 21 changes on top of dfranzen's Milestone~2 notebook for the ARC Prize 2026 ARC-AGI-3 Kaggle
competition (offline, 9~hours, one RTX PRO 6000, 110 hidden interactive games, RHAE score). Changes were
screened on a 25-game local run, on a 40-episode stuck-level suite, and by public submission. One configuration,
the D$'$ slot priority from a public notebook, leads plain dfranzen by 1.7 public points over three draws each
($p\approx0.34$). No change we built moved the public score, and no local or suite result outside the noise
band reproduced.
\end{abstract}

\section{Setup}
The base is dfranzen's notebook: Qwen3.8-Flash-Next (W4A16) with a multi-token-prediction drafter, served by SGLang
``Pennyroyal'' 2.5.3, driving a Python-tool agent harness over 10 concurrent game streams with a priority
scheduler. Kaggle allows one submission per day; the public score covers about 55 of the 110 hidden games.

Three screens, with their measured noise:
\begin{itemize}
  \item \textbf{Public score}: identical plain copies scored 28.39, 27.86 and 24.60 (sd 2.05); community copies
        average 25.77 (sd 3.93).
  \item \textbf{Local 25-game run} (RHAE on the public games): identical runs differ by up to about 7 points.
  \item \textbf{Stuck-level suite}: 20 levels where full runs got stuck, each replayed twice from the recorded
        history; identical baselines cleared 9 and 9 of 40 episodes (sd about 3.7), so a gain needs about 16.
\end{itemize}

Of 28 re-attempts (v3 and v4), 6 cleared their level afterwards (21\%), against about 25\% of stuck levels
cleared by continuing in unmodified runs.

\section{Findings}
\begin{enumerate}
  \item Scheduler changes that move time between games won locally and lost publicly (20.60, 22.56): the 25-game
        local mix does not represent the 110 hidden games.
  \item The model depends on its own past reasoning: removing it collapsed the run to 24.27.
  \item Restarting a stuck level, with or without its context, converts it no more often than continuing.
  \item Smaller board images (256 px) cost nothing and add 5\% throughput.
  \item A submission from a newly created kernel scored 0.00 although its save run passed; the same code from an
        existing kernel scored normally.
\end{enumerate}

\section{What is not established}
\begin{itemize}
  \item Whether D$'$ beats plain dfranzen: resolving 2 points needs about 60 draws per arm.
  \item Any local effect under about 5 points.
  \item The cause of the new-kernel 0.00: no scored-rerun logs are available; a Python 3.13 image change, a
        dataset-version race and mount failures all fit.
  \item What the teams above 40 do: none of the top five has disclosed a method.
  \item Whether 256 px images change the public score.
\end{itemize}
