\begin{abstract}
We tested 26 changes on top of dfranzen's Milestone~2 notebook for the ARC Prize 2026 ARC-AGI-3 Kaggle
competition (offline, 9~hours, one RTX PRO 6000, 110 hidden interactive games, RHAE score). Changes were
screened on a 25-game local run, on a 40-episode stuck-level suite, and in 33 public submissions. The D$'$ slot priority from a public
notebook and plain dfranzen are within noise: 27.37 (8 draws) against 25.56 (5 draws), with draws of
identical code spread over 22--30. One change cleared every draw of the kernel without it: solved-level memory, which pins
the model's own one-line rule for each cleared level into the system prompt, scored 32.64 and 28.01 against 25.53 over
five draws of the same kernel without it (Welch $t=1.97$, $n=2$). Our best public score, 32.64, ranks 296 of 5{,}070.
\end{abstract}

\section{Setup}
The base is dfranzen's notebook: Qwen3.8-Flash-Next (W4A16) with a multi-token-prediction drafter, served by SGLang
``Pennyroyal'' 2.5.3, driving a Python-tool agent harness over 10 concurrent game streams with a priority
scheduler. Kaggle allows one submission per day; the public score covers about 55 of the 110 hidden games.

Three screens, with their measured noise:
\begin{itemize}
  \item \textbf{Public score}: identical plain copies scored 28.39, 27.86, 24.60 and 25.21; with D$'$'s four draws the sd is about 2.8; community copies
        average 25.77 (sd 3.93).
  \item \textbf{Local 25-game run} (RHAE on the public games): identical runs differ by up to about 7 points.
  \item \textbf{Stuck-level suite}: 20 levels where full runs got stuck, each replayed twice from the recorded
        history; identical baselines cleared 9 and 9 of 40 episodes (sd about 3.7), so a gain needs about 16.
\end{itemize}

\subsection*{Stuck-level suite (episodes cleared of 40; baseline 9, 9)}
Stall probe 10; prompt candidates 11, 11, 12, 9, 5; win records 8; thinking cap 8; keep-context restart 8; replay-verified simulator check 8
(the contract reached all 40 transcripts, none wrote the \texttt{predict} function it asked for).

\subsection*{Re-attempt conversion}
Of 28 re-attempts (v3 and v4), 6 cleared their level afterwards (21\%), against about 25\% of stuck levels
cleared by continuing in unmodified runs.

\subsection*{Serving speed}
Speculative-decoding settings, 100 real requests at 10 concurrent: dfranzen's 3 draft steps with the FR-Spec
vocabulary gave 400 and 419 tok/s on two boots; 2 steps 393, FR-Spec off 392, no speculative decoding 312.
4 and 5 steps did not boot within 20 minutes. Replaying the scheduler over three local runs with a throughput
multiplier gave 50.5 (stock), 52.4 (+10\%), 54.3 (+20\%) and 57.2 (+30\%); the replay overstates the stock run
(50.5 against 42.7 measured), so these are direction and rough size.

\subsection*{Phase 2 changes (14 October--2 November)}
\textbf{Keep-alive.} From 10-20 scored machines took 35--63 minutes to load weights, longer than the 15 minutes Kaggle
allows a scorecard without an action; three draws scored 0.00 and one errored. A watchdog cell RESETs one live game
whenever no action has gone out for 5 minutes while the server loads (10 once it is up). All nine draws after it scored.

\textbf{Turn archive.} The model's own trimmed turns, searchable from the Python tool. Two draws (26.41, 24.39) fell under
the gate fixed beforehand (two-draw mean $\le 27$ drops it).

\textbf{Solved-level memory.} Taken from a public notebook (vickyfym, after rellik13/sirikilohit, CC-BY 4.0). When a level clears, the next
two turns ask for one ``Rule for level $N$:'' line; the rule, the winning attempt's last 30 actions and the clearing turn's
reasoning are pinned at the end of the system prompt, rewritten only when the conversation drains so the prompt cache
survives. Its save run (one game, 45K tokens) captured four rules with no errors but never drained, so our gate
(at least one pin) failed. We overrode the gate after seeing why; the two public draws are the first full-length test.

\section{Findings}
\begin{enumerate}
  \item Scheduler changes that move time between games won locally and lost publicly (20.60, 22.56): the 25-game
        local mix does not represent the 110 hidden games.
  \item The model depends on its own past reasoning: removing it collapsed the run to 24.27.
  \item Restarting a stuck level, with or without its context, converts it no more often than continuing.
  \item Smaller board images (256 px) cost nothing and add 5\% throughput. dfranzen's speculative-decoding settings
        are already the fastest tested; the remaining speed lever is a drafter retrained on the quantised model.
  \item Asked to write a checkable simulator of the game, the model declined in every episode and called it
        optional: it predicts in prose, not in code.
  \item A submission from a newly created kernel scored 0.00 although its save run passed; the same code from an
        existing kernel scored normally.
  \item The model's own stated rules carried across a drain lifted the score where every attempt to carry raw
        history, records or notes had not: 30.33 over two draws against 25.53.
  \item Late in the competition infrastructure, not policy, decided draws: five of eight draws from 10-17 to 10-24 failed
        in the scored rerun before the keep-alive.
\end{enumerate}

\section{What is not established}
\begin{itemize}
  \item Whether solved-level memory is a real gain: two draws, and 28.01 sits inside the range of the kernel without it.
  \item The private score, which Kaggle withholds until the close; public covers about 55 of the 110 hidden games.
  \item Whether D$'$ beats plain dfranzen: 27.37 against 25.56; resolving 2 points needs about 60 draws per arm.
  \item Whether a 10--15\% throughput gain shows publicly: the replay puts it near +1--1.5 points, below what
        eight draws per arm can detect.
  \item Any local effect under about 5 points.
  \item The cause of the new-kernel 0.00: no scored-rerun logs are available; a Python 3.13 image change, a
        dataset-version race and mount failures all fit.
  \item What the teams above 40 do: the top three have not published code.
  \item Whether 256 px images change the public score: the one draw with them (and the retrained drafter) scored 24.10.
\end{itemize}
